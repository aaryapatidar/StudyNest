# StudyNest

StudyNest is a focused student productivity workspace for subjects, notes, tasks, resources and revision. It is designed as an M.Sc. Computer Science 4th semester project: simple enough to understand quickly, structured enough to extend into a production system.

## Features

- Calm responsive dashboard with study summaries and quick actions
- Subject, note, task, resource and revision views
- Search across notes and workspace content
- Favorite notes, task completion, progress view and theme preference
- FastAPI auth and protected CRUD API
- OpenAPI documentation, tests, Docker Compose and academic documentation

## Stack

React, TypeScript, Vite, React Router, Lucide React, FastAPI, Pydantic, SQLAlchemy/PostgreSQL-ready configuration, JWT and Docker.

## Run locally

### Prerequisites

- Node.js 18+ and npm
- Python 3.11+ (for backend development without Docker)
- PostgreSQL 16+ (for production; SQLite works for development)

### Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

The frontend opens at `http://localhost:5173`.

### Backend

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --reload
```

The API opens at `http://localhost:8000`; interactive docs are available at `http://localhost:8000/docs`.

### Docker

Copy `.env.example` to `.env`, update `SECRET_KEY`, then run `docker compose up --build`.

Frontend: `http://localhost:5173` · API: `http://localhost:8000/docs` · PostgreSQL: `localhost:5432`.

## Project structure

```text
frontend/src/       React application, reusable layout and feature screens
backend/app/        FastAPI application, auth, schemas and API routes
backend/tests/      API smoke and authorization tests
docs/               project report and Mermaid diagrams
docker-compose.yml  frontend, backend and PostgreSQL services
```

## Deployment

Build the frontend with `npm run build` and deploy its `dist` folder to Vercel, Netlify or a static host. Deploy the backend Docker image to Render, Railway or another container platform, point `DATABASE_URL` at managed PostgreSQL, set a unique 32+ character `SECRET_KEY`, set `ENVIRONMENT=production`, and set `CORS_ORIGINS` to the exact deployed frontend URL. The API refuses the development signing key when `ENVIRONMENT=production`.

## API

The canonical API reference is generated by FastAPI at `/docs` and `/redoc`. Main groups are `/api/auth`, `/api/subjects`, `/api/notes`, `/api/tasks`, `/api/resources`, `/api/dashboard`, `/api/progress` and `/api/notifications`.
